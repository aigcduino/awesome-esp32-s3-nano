## Start here

The WT9932S3-NANO is an ultra-compact Nano-form-factor board built on an **ESP32-S3R8**:

- **MCU** — ESP32-S3R8, Xtensa LX7 dual-core @ 240 MHz, 384 kB ROM + 512 kB SRAM
- **Memory** — 16 MB flash + 8 MB PSRAM
- **Radio** — 2.4 GHz Wi-Fi and Bluetooth LE, USB HID capable
- **Power** — 3.3 V operation, 5 V input via VIN, VBUS or USB-C
- **Buttons** — on-board BOOT and RESET
- **Edge** — castellated half-hole pads, so the board can be soldered flat onto your own PCB
- **Toolchains** — Arduino, MicroPython, ESP-IDF; Arduino IoT Cloud ready

It is pin-for-pin compatible with the Arduino Nano ESP32, which is what makes this list useful:

| | WT9932S3-NANO | Arduino Nano ESP32 |
|---|---|---|
| MCU module | ESP32-S3R8 | u-blox NORA-W106 (ESP32-S3) |
| Flash | 16 MB | 16 MB |
| Pin layout | identical `D0–D13` / `A0–A7` | reference |
| Castellated half-hole pads | yes | no |

Two practical consequences:

1. **Select `Arduino Nano ESP32` in your IDE and it just works.** Uploads go over DFU (`2341:0070`), exactly as shown in the official [getting-started guide](https://wiki.wireless-tag.com/docs/en/WT9932S3-NANO/getting_started.html).
2. **The memory configuration already matches the core.** The Espressif core's `nano_nora` board definition targets 16 MB flash and OPI PSRAM, so the on-board 8 MB PSRAM is usable without a custom board variant or partition table edit.

### Pinout

`D0–D13` / `A0–A7` are Arduino pin names, **not** GPIO numbers. This is the documented mapping:

| Left header | GPIO | Right header | GPIO |
|---|---|---|---|
| D13 | GPIO48 (SPI SCK) | D12 | GPIO47 (SPI MISO) |
| 3.3V | — | D11 | GPIO38 (SPI MOSI) |
| B0 | GPIO46 | D10 | GPIO21 |
| A0 | GPIO1 | D9 | GPIO18 |
| A1 | GPIO2 | D8 | GPIO17 |
| A2 | GPIO3 | D7 | GPIO10 |
| A3 | GPIO4 | D6 | GPIO9 |
| A4 | GPIO11 (I2C SDA) | D5 | GPIO8 |
| A5 | GPIO12 (I2C SCL) | D4 | GPIO7 |
| A6 | GPIO13 | D3 | GPIO6 |
| A7 | GPIO14 | D2 | GPIO5 |
| VBUS | 5 V | GND | — |
| B1 | GPIO0 (BOOT) | RST | — |
| GND | — | D0 | GPIO44 (RXD) |
| VIN | 5 V | D1 | GPIO43 (TXD) |

## Quickstart

Arduino IDE: install the **esp32** board package (by Espressif), then select **Arduino Nano ESP32**.

PlatformIO:

```ini
[env:nano]
platform = espressif32
board = arduino_nano_esp32
framework = arduino
```

arduino-cli:

```bash
arduino-cli core install esp32:esp32
arduino-cli compile --fqbn esp32:esp32:nano_nora .
```

## Board support & cores

- [espressif/arduino-esp32](https://github.com/espressif/arduino-esp32) - The Arduino core that actually ships the `nano_nora` board definition — 16 MB flash, OPI PSRAM, DFU upload, plus the "Arduino pin / native GPIO" menu. *(★17.7k)*
- [arduino/arduino-esp32](https://github.com/arduino/arduino-esp32) - Arduino's own ESP32 core. It only ships the bare `nora_w10` module variant (4 MB flash, QSPI PSRAM), which is **not** a complete Nano ESP32 board. *(no board support, ★43)*
- [platformio/platform-espressif32](https://github.com/platformio/platform-espressif32) - `board = arduino_nano_esp32` in `platformio.ini` gives an ESP32-S3 / 16 MB setup with the Arduino core. *(★1.2k)*
- [micropython/micropython](https://github.com/micropython/micropython) - `ports/esp32/boards/ARDUINO_NANO_ESP32` is the official MicroPython board definition. *(★22.2k)*
- [adafruit/circuitpython](https://github.com/adafruit/circuitpython) - `ports/espressif/boards/arduino_nano_esp32s3` — CircuitPython with UF2 flashing. *(★4.6k)*
- [RIOT-OS/RIOT](https://github.com/RIOT-OS/RIOT) - `BOARD=arduino-nano-esp32` in the Makefile. *(★5.8k)*
- [tinygo-org/tinygo](https://github.com/tinygo-org/tinygo) - Go for microcontrollers. No Nano ESP32 target yet — use `-target=esp32s3-generic`. *(generic ESP32-S3, ★17.9k)*
- [esp-rs/esp-hal](https://github.com/esp-rs/esp-hal) - Bare-metal Rust HAL. Enable the `esp32s3` feature; there is no board crate for this one. *(generic ESP32-S3, ★2.2k)*
- [espressif/esp-idf](https://github.com/espressif/esp-idf) - Official Espressif framework. Target `esp32s3`, then set flash size and OPI PSRAM yourself. *(generic ESP32-S3, ★19.4k)*
- [Wireless-TAG-Maker/WT_BSP](https://github.com/Wireless-TAG-Maker/WT_BSP) - Wireless-TAG's own board support package for ESP-IDF — unified RGB LED, button, display and camera API. Officially targets the TINY series; check `idf.py set-board` before assuming NANO support. *(generic ESP32-S3, ★8)*

## Before you flash

- **Uploads go over DFU, not a plain serial port.** To force download mode: hold **BOOT** (GPIO0), tap **RESET**, release BOOT.
- **`D0–D13` / `A0–A7` are not GPIO numbers.** The board definition has a `PinNumbers` menu (`By Arduino pin` / native GPIO); the table above is the source of truth. Copying a sketch without checking this is the #1 cause of "the code is right but nothing works".
- **The default partition only gives your app 3 MB** (`app3M_fat9M_fact512k_16MB`). A 16 MB chip does not mean a 16 MB app — use a custom partition table for large images or model weights.
- **`loop()` runs on core 1** (`ARDUINO_RUNNING_CORE=1`), so dual-core code that assumes core 0 will bite you.
- **USB defaults to HW CDC** (`usb_mode=0`, `cdc_on_boot=1`). Switching to HID makes the serial port disappear — expected.
- **Board documentation lives on the vendor wiki, not GitHub** — [wiki.wireless-tag.com](https://wiki.wireless-tag.com/docs/en/WT9932S3-NANO/board_features.html) (features, pinout, getting started, datasheet PDF). The vendor's GitHub org is [`Wireless-TAG-Maker`](https://github.com/Wireless-TAG-Maker).
